## Executive summary

**Corpus.** 10 merged public Java PRs, one per ticket category, from 8 repositories:

- apache/commons-lang, spring-projects/spring-boot (2), google/gson, mockito/mockito (2),
  FasterXML/jackson-databind, keycloak/keycloak, spring-projects/spring-petclinic,
  spring-projects/spring-framework.
- They range from 2 files and 28 lines to 63 files and about 1000 lines.
- All were evaluated read-only. Athena ran in standalone-Diff mode with no GitHub
  token, so nothing was written to any PR.

**Headline.** Athena is good at one thing: **recognizing and naming structural
relocations**, meaning members moved between classes and responsibilities pulled into new
types. When a PR is *made of* such operations, Athena beats the diff. On
`spring-petclinic-1913` it pulled the only design change out of a 63-file,
29-copyright-files PR as one `Move OwnerRepository#findPetTypes -> PetTypeRepository`
entry.

Everywhere else, the dominant finding is **missing information, silently**:

- **Body edits are invisible.** 3 of 10 PRs produced **zero** Changes, and 2 more showed
  only their new test. The commons-lang fix, the gson refactoring, the mockito nullness
  contract, the spring-boot config property and the spring-framework concurrency fix all
  changed code *inside* method bodies, in nested classes, or in annotations. Athena
  doesn't model any of those.
- **No UI signal.** The UI only reaches raw diff through a Change. A file with no Change
  has no path in the UI at all, and nothing tells the reviewer something is missing.

**Coverage of changed production Java files** (share appearing in at least one Change):

| | |
|---|---|
| Median | **0.25** |
| 0% | 5 of 10: commons-lang, gson, mockito-3784, spring-boot-51774, spring-framework |
| 100% | only jackson-databind-6209 |

**Most significant strengths:**

1. **Move/relocation detection with naming.** `MOVE_SYMBOL` and `MOVE_FIELD`
   across classes and into new abstract bases (petclinic, keycloak).
2. **Class-grouped change inventory.** On structural PRs (jackson, keycloak) it's
   faster to scan than 30–50 diff hunks.
3. **Recognizing a new Repository/port/factory.** petclinic and keycloak.

**Most significant weaknesses:**

1. **Behavioral and body-level edits aren't represented at all.** The BEHAVIORAL
   category can't be produced by the pipeline.
2. **Nested types, enum constants, annotation elements and parameter annotations
   are invisible.**
3. **Empty or partial results look identical to complete ones.**
4. **Incorrect inference:**
   - `EXTRACT_METHOD` reports "extractions" from files the PR never touched (keycloak).
   - Tests are labelled as new business capabilities.
   - Relocations are labelled "Remove Capability".
5. **Architecture views are uninformative.**
   - Modules are named after the first path segment (`src`, `module`).
   - Tech stack is "Unknown" for every Gradle or single-module repo.
   - Dependency rails: 0 in every PR.
6. **Cost scales with repository size, not PR size.** 12 minutes for a 3-file
   spring-boot PR; 25 minutes for a 2-file spring-framework PR; 27 minutes for keycloak.

**What kind of understanding is Athena uniquely good at today?** *Relocation
understanding*: "this responsibility now lives there, and these consumers were rewired".
It's strongest in noisy PRs, where a diff buries it.

**Where does it fail to provide what it's designed for?** *Intent and impact*. The
Capability/Intent layers are mostly counts of generic Add/Remove cards, and behavior is
never represented.

### 1. `commons-lang-1794`: small bug fix

```text
PR:                apache/commons-lang#1794 — LANG-1834 Fix Fraction reduction for Integer.MIN_VALUE
URL:               https://github.com/apache/commons-lang/pull/1794
Category:          small-bug-fix
Athena snapshot:   snapshots/a5bb763/commons-lang-1794
```

**Reference understanding.** `Fraction.getReducedFraction(int, int)` threw
`ArithmeticException` for representable fractions such as `MIN_VALUE / -2`: sign
normalization negated `Integer.MIN_VALUE` before any reduction happened. The fix turns a
one-off `if (denominator == MIN_VALUE && numerator even)` halving into a `while (both even)`
loop that runs before sign normalization. That changes behavior for every even/even input,
not just the edge case. A test pins the edge cases, including the ones that must still
throw.

**Diff understanding.** 2 hunks in 2 files. The `if` → `while` swap and the rewritten
comment are both visible in 4 changed lines. The test spells out the edge cases.
Understanding is essentially complete from the diff alone.

**Athena understanding.** One Change: `Add FractionTest#testReducedFactoryIntegerMinValue`
(structural). One Explorer card, "Add Capability" (inferred, 70%), for a test method. The
Canvas shows territory `src`, tech stack "Unknown". The Review Briefing's single focus
area is the test. **The production fix isn't represented anywhere**: `Fraction.java` has 0
Changes, and the UI only reaches raw diff through a Change. A reviewer who trusts Athena
would conclude this is a test-only PR.

| Axis | Diff | Athena | Why |
|---|---|---|---|
| What | 4 | 1 | Athena shows only the test; the edited method is absent. |
| Why | 3 | 1 | The test name hints at `MIN_VALUE`; the fix's comment isn't reachable. |
| Impact | 3 | 0 | The broadened reduction (all even/even inputs) can't be seen. |

**Effort (agent reading-effort proxy):**
- Diff: 2 hunks / 2 files.
- Athena: 1 entry, then the full diff anyway, because the fix is missing.

**What Athena made easier:**
- Nothing for this PR.

**What Athena failed to show:**
- The only production change: a condition and control-flow edit inside
  `getReducedFraction`.

**Unexpected:**
- A test method is labelled a new business capability.
- The PR's single territory is named `src`.

**Most valuable Athena insight:**
- None.

**Biggest problem:**
- Silent omission. Nothing in the UI says "1 changed production file has no Change".

**Diff → understanding gap:**

```text

               not only the MIN_VALUE edge case.
```

### 5. `jackson-databind-6209`: architectural change

```text
PR:                FasterXML/jackson-databind#6209 — Fix #6198: make AnnotatedMethod InvokerHolder access lazy
URL:               https://github.com/FasterXML/jackson-databind/pull/6209
Category:          architectural
Athena snapshot:   snapshots/a5bb763/jackson-databind-6209
```

**Reference understanding.** Removes the internal `UnreflectHandleSupplier` abstraction,
whose per-instance holder objects were allocated eagerly. `AnnotatedMethod`,
`MethodProperty` and `BeanPropertyWriter` now resolve their `MethodHandle`s lazily and
cache them in `volatile` fields, using the same racy-publication pattern already used
elsewhere. Fixed `MethodType`s become `static final` constants. The payoff is about 16%
faster (de)serializer construction and less retained heap.

**Compatibility risk:** 6 `protected` fields change type, from holder types to
`MethodHandle`. That breaks source compatibility for subclasses.

**Diff understanding.** 8 files, 33 Java hunks. The lazy-handle pattern repeats 3 times and has
to be recognized per file. The protected-field type change is easy to miss among other
edits. The PR description's benchmark is what explains *why*.

**Athena understanding.** 40 Changes, all structural, grouped by class, covering 100% of
changed Java files:
- `UnreflectHandleSupplier` removal, as 8 separate entries (class plus 7 members).
- New `invoker*` / `_unreflect*` / `_*Handle` methods.
- New `static final` `*_TYPE` constants.
- Each field whose type changed, as a **Remove field + Add field of the same name**:
  `_invokerNullary`, `_invokerUnary`, `_invokerFixedArity`, `_setter`, `_setterReturn`,
  `_accessor`.

The Explorer shows 42 cards: "Add ×26", "Remove ×14", "Add Capability (groups 26)",
"Remove Capability (groups 14)". The focus areas are 4 new test methods, picked
alphabetically from a tie.

| Axis | Diff | Athena | Why |
|---|---|---|---|
| What | 3 | 3 | Athena's per-class inventory is complete and easier to scan than 33 hunks, but noisy. |
| Why | 2 | 1 | Neither shows the performance motive. Athena's capability cards are pure counts. |
| Impact | 2 | 1 | The field-type change appears as remove/add pairs, not as an API-compatibility change. |

**Effort:**
- Diff: 33 hunks / 8 files.
- Athena: 40 entries plus 42 cards. Complete, but longer to read than the diff.

**What Athena made easier:**
- A complete, per-class inventory, with the removed abstraction's whole surface in one
  place (`[UnreflectHandleSupplier]` group).
- Seeing that the three classes each gained parallel `*Handle`/`_unreflect*` members.

**What Athena failed to show:**
- "Field type changed" as a first-class change. It's the actual compatibility risk.
- The relationship "responsibility of X inlined into A, B, C".
- A repeated-pattern group for the same lazy-handle idiom in 3 classes.

**Unexpected:**
- A removed class is listed member by member (8 entries) instead of once.
- The focus areas ignore the production classes entirely.

**Most valuable Athena insight:**
- The class-grouped inventory makes the symmetry across `AnnotatedMethod`,
  `MethodProperty` and `BeanPropertyWriter` visible at a glance.

**Biggest problem:**
- Volume without synthesis. 82 entries and cards tell the reader *what* but not the one
  architectural sentence that matters.

**Diff → understanding gap:**

```text
Observation:   6 protected fields changed type (holder → MethodHandle): a source-compat break for subclasses.
Conventional diff: Visible per file, but only if the reviewer checks field declarations in 3 files.
Athena:        Shown as 6 × (Remove field X, Add field X) — the information is there, but not as "type changed", and
               nothing marks protected API.
Result:        Mixed: Athena lists every affected field in one place, but its representation obscures what happened.
Evidence:      changes.json REMOVE_FIELD/ADD_FIELD pairs with identical names in AnnotatedMethod, MethodProperty,
               BeanPropertyWriter.
```

### 7. `spring-boot-51490`: cross-module change

```text
PR:                spring-projects/spring-boot#51490 — Use constructor injection in classes that participate in @Import
URL:               https://github.com/spring-projects/spring-boot/pull/51490
Category:          cross-module
Athena snapshot:   snapshots/a5bb763/spring-boot-51490
```

constructor injection for these. Fields become `final`, and `NullAway.Init` suppressions

implementing Aware interfaces, so the migration can't regress.

**Diff understanding.** 8 files, 18 hunks. Recognizing it as *one* migration takes reading

framework contract (Spring instantiating `@Import` participants with constructor

and `ManagementContextConfigurationImportSelector` Athena shows a clear trio: `Remove
setBeanFactory` / `setBeanClassLoader`, `Change annotations on field`, and `Add

shows only the setter removal: its new constructor uses a ternary, so it isn't a
"straight assignment". `ArchitectureRules` shows 3 added methods.

- **3 of 7 production files**: `ImportsContextCustomizer.ImportsSelector` and both

- The removal of `implements BeanFactoryAware` from each class header.

```bash
evaluation/tools/summarize.py evaluation/snapshots/<sha>/<id>
```

## Limitations

- **Sample size.** 10 PRs, one per category. It shows patterns, not rates.
- **Single evaluator.** One evaluator, an agent, did both the diff and the Athena pass,
  in that order. The Athena pass may be anchored by the diff pass; the protocol accepts
  this and records the order.
- **No human timings.** Effort is recorded as reading-effort proxies, not minutes.
- **Deterministic layers only.** Athena's AI features were deliberately excluded (ticket
  non-goal: "don't benchmark Claude"). These are the AI briefing summary, uncertainty
  questions and module narratives. They may compensate for some of the gaps above, which
  would be worth a separate, clearly labelled evaluation.
- **UI checked on one PR.** The UI was inspected visually on one PR. All other Athena
  output comes from Athena's own controllers and view classes run in-process
  (`tools/AthenaSnapshot.java`), which produce the same JSON the UI renders.
- **Snapshot date.** SHAs are pinned. PR descriptions and diffs were fetched on
  2026-09-23.
