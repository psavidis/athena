## Findings

1. **L1: #363's folding adds cards when parallel test classes gain same-named members.**
   - #363 folds test changes of the same kind and member across test classes. That's right for a refactoring (assertj-4338), but it also fires on new tests and fixtures that happen to share names:
     - kafka-23542 adds the same seven tests to `GroupMetadataManagerTest` and `StreamsGroupStaticMemberGroupMetadataManagerTest`: **8 → 16 cards**;
     - hibernate-orm-13477's test entities all gain `id`, `name`, `active`: `Add id in 5 test classes`, 12 fold cards, **85 → 98**;
     - keycloak +5, camel-26805 +3, junit5-6057 +2.
   - Each fold becomes its own card while the classes keep their `Test changes in X` cards, so the view gets longer, not shorter.
   - **Suggested rule:** fold test changes only when the fold replaces whole per-class cards, or only for removals and renames (a refactoring's signature), not additions.
   - The same limit is why assertj-4338 stops at 17 cards instead of ≤ 12: 8 of its classes keep a card for their non-repeating changes.
2. **L2: an argument item can repeat a receiver change.** spring-petclinic-1913 reads
   `+types.findPetTypes, -owners.findPetTypes, given(…): owners -> types`. The `given(…)` item
   restates the swap already shown. Minor. Skip an argument item when the differing text is the
   receiver of a call already listed as added or removed.
3. **Still open:**
   - rails between kafka's projects, which reference each other from root `project(':x') { … }` blocks (#362's out-of-scope follow-up);
   - the #338 follow-up (spring-security `config` ↔ `web` rail);
   - H6 (Groovy/Spock tests, micronaut-13421);
   - J4 (Maven plugin configuration, dropwizard-11325);
   - assertj-4338's `Rename BaseAssertionsTest#<instance-init> -> setUpStackTraceFiltering` wording.

## Limitations

- **In-sample.** The third expansion drove #357–#363, so its gains measure fix correctness,
  not generalization.
- **Single agent evaluator.** The re-scored entries were judged by the same agent that
  implemented the fixes, so the gains deserve an independent look.
- **Only changed views were re-scored.** An entry whose Athena output is identical, or changed
  only in wording, keeps its previous score.
- **#359 unexercised on the corpus.** No network fault occurred in this run.
