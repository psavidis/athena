**What moved.** Every item the second report ranked was delivered, and each one's corpus
definition of done was met:

- **Test code is known and kept out of the way** (#285, #286, #287).
  - Focus areas are production-first. petclinic leads with its Move, mockito-3835 includes `Spy#mockMaker`, and jackson and spring-boot-51490 no longer list test methods.
  - The Explorer folds test changes into one entry per test class. mockito-3835 goes from 26 cards to 14, and 13 test changes become one "Test changes in SpyAnnotationTest".
- **Body modifications say what changed** (#288). keycloak's security trigger point reads `+detail, +error, +clientPolicy, +triggerOnEvent, …`. jackson's rewiring reads `+invokerUnary, -get` twelve times, which spells out the reflection → `MethodHandle` switch.
- **`switch` is control flow** (#289). gson's refactoring reads as a rewrite, not as nine removed branches.
- **Repeated operations read once** (#290, #291).
  - keycloak's pull-up into two new base classes is five `Pull up …` entries naming every source class, instead of one move plus eleven removals. keycloak goes from 112 Changes to 91.
  - spring-boot-51490 reads `Remove setBeanFactory in 5 classes`.
  - Two runs give byte-identical output.
- **The Canvas describes real modules** (#292, #293). spring-boot-51490 shows its six touched modules by name, each "Spring Boot · Java", with 29 rails. commons-lang is `commons-lang3`, not `src`.
- **Spring semantics** (#294, #295).
  - All six spring-boot-51490 participants read "Spring: Aware Callback to Constructor Injection".
  - spring-boot-51774 names the property it adds: `spring.kafka.listener.await-async-results-on-stop`.
- **Label hygiene** (#296). There are no more `+@Override` entries, and mockito-3784 reads "Change Contract Annotations".

**What is still weak:**

1. **Idle territories explode on large, well-connected repos (N6).**
   - keycloak now shows 35 territories (3 touched, 32 idle) and 35 rails; spring-boot-51490 shows 20.
   - The rails are real, but "everything the touched modules depend on" is too much for a first view.
2. **Custom-named Gradle build files aren't recognized (N7).** spring-framework names its module build files `<module>.gradle`, via `project.buildFileName`. So `spring-core` isn't found as a module, and the one territory is the root project, `spring`.
3. **Assignments and field accesses aren't summarized (N8).** 7 of petclinic's 9 body modifications and keycloak's 6 constructor edits read "other statements changed". What they changed is which field or repository they use.
4. **Why is still the gap on small PRs.** commons-lang, spring-framework and spring-boot-51774 are still behind the diff. Athena says *what* precisely, but not *why* (the MIN_VALUE overflow, the eviction race). Deterministically, that's the limit without an AI narrative.

## New findings

- **N6: Idle territories aren't bounded.** #293 adds every module a touched module depends on
  as an idle territory: 32 for keycloak's test-framework `base` module, 14 for spring-boot-51490
  and 8 for spring-boot-51774. They're accurate, but the Canvas's first view should favour the
  touched modules, for example by showing only rails *between* touched modules until asked.
- **N7: Custom Gradle build-file names.** Projects that set `project.buildFileName` (spring-framework:
  `spring-core/spring-core.gradle`) have module directories without a `build.gradle`, so the
  module falls back to the root project. Honouring `*.gradle`/`*.gradle.kts` named after the
  directory, or reading `settings.gradle`'s `include`s, would fix it.
- **N8: Body summaries miss assignments and receiver changes.** "Other statements changed" is
  the summary for 7 of petclinic's 9 body edits (`owners.findPetTypes()` → `types.findPetTypes()`)
  and for keycloak's 6 constructor edits (a field assignment moved to `super(...)`). Receivers of
  calls and assigned fields are the next two things to add.
- **N9: Framework classifications aren't folded.** The Structural level folds repeated changes
  (#291), but the six identical "Aware Callback to Constructor Injection" entries stay
  separate.

## Limitations

These are the same as the earlier reports' limitations, in particular:

- **One evaluator.** The same agent implemented #285–#296 and scored this run, so the
  Athena-side scores may be biased upward. The mechanical metrics (cards, territories, rails,
  coverage, the per-ticket corpus checks) should carry more weight.
- **Output-level only.** There was no visual pass of the UI.
- **The corpus shaped the tickets.** Each ticket's definition of done was a corpus PR, so the
  gains here are partly in-sample. Adding new PRs to the corpus before the next batch would
  show how well they generalize.
