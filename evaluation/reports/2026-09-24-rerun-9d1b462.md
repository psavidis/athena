## Findings

- **G1: "same calls" appears on real bug fixes.** netty-17589's race fix and commons-lang-1794's
  MIN_VALUE fix change only conditions and branches, so they also carry `; same calls`. That's
  why #319 worded it "same calls" rather than "same operations": it states what was checked
  and nothing more. It stays BEHAVIORAL. Watch whether reviewers read it as reassurance anyway.
- **G2: Modifier detection is a design signal, not only noise.** `+volatile, -final`
  (jackson-6209) and `+final` on injected fields (spring-boot-51490) are the kind of facts a
  diff buries. Folding keeps the sweep case (guava-8651) readable in the Explorer.
- **G3: The Change Map doesn't fold what the Explorer folds.** guava-8651 has 437 Changes. The
  Explorer shows 9 cards, but the Change Map and the class groups still list every
  `+final` member.
- **G4: Long values say only "value changed".** petclinic's `container` field and
  commons-io's `EMPTY_BUFFER` get no summary, because their initializers are long constructor
  calls. A token-level summary of what differs (for example `ByteBuffer.allocate(0) ->
  ByteBuffer.allocateDirect(0)`, trimmed) would help.
- **Still open from earlier runs:**
  - the closed-unmerged rejection reasons (leaks, performance, design), which need
    consequence-level reasoning;
  - dependency changes in build files and `module-info.java`;
  - relating a behavioral change to the state it guards (spring-framework, netty).

## Limitations

- **Same evaluator throughout.** The same agent planned, implemented and scored this batch,
  so the scores may be biased upward. The definition-of-done table and the metrics are
  mechanical and should carry more weight.
- **Partly in-sample now.** The 16 expansion entries were this batch's definitions of done.
  A fresh set of PRs is needed to measure generalization again.
- **Output-level only**, apart from #318, which was verified with frontend tests rather than a
  visual pass.
