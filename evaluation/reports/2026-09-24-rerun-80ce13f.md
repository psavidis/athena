## Executive summary

All ten corpus PRs were re-run in **1 min 53 s in total**, including anonymous checkouts. The
baseline run took about 1.5 hours, because the three large repositories needed 12–27 minutes
each. Every analysis is `READY` with no degraded files.

**Headline changes since the baseline:**

| Measure | Baseline (`a5bb763`) | Now (`80ce13f`) |
|---|---|---|
| PRs where Athena showed **zero** Changes | 3 of 10 | **0 of 10** |
| PRs where Athena showed only the new test | 2 of 10 | **0 of 10** |
| Median production-Java file coverage | **0.25** | **1.00** |
| PRs with full production-Java coverage | 1 of 10 | **8 of 10**¹ |
| Changes citing a file the PR never touched | 3 (keycloak) | **0** |
| BEHAVIORAL Changes produced (whole corpus) | 0 (category unreachable) | 15 |
| Slowest analysis | 1604 s (keycloak) | **18.5 s** (keycloak) |

| PRs where Athena ≥ the diff (What+Why+Impact) | 1 | **3**, plus 1 within 1 point |

¹ The two exceptions:
- `mockito-3784/module-info.java`: module descriptors aren't modelled. It's still reachable through the new "unrepresented files" list.
- `spring-petclinic-1913/PetClinicApplication.java`: the only edit is a removed blank Javadoc line, which no detector reports. That's correct, and the file is listed as "no semantic change detected".

**What moved.** Nearly every "missing information" root cause from the baseline is fixed. Athena
no longer silently hides:

- edits inside method bodies (#264);
- condition and control-flow changes (#263);
- nested classes (#265);
- enum constants and annotation elements (#266);
- field type changes (#267);
- contract annotations (#268).

When something *is* still unmodelled (build files, `module-info`, SPI registrations), the new
coverage indicator names it and opens its raw diff (#260/#261). The keycloak phantom
extractions are gone (#269), and a fix made during #263 means same-named types in different
packages are no longer compared with each other.

**What didn't move, and what got worse:**

1. **Signal-to-noise.** Showing everything means showing a lot. keycloak now produces 112
   Changes and 126 Explorer cards (baseline: 82/92), jackson 54/57 and mockito-3835 22/26.
   Much of the growth is test code: nested test-fixture classes and test-method body edits.
   Nothing separates or down-ranks it (R7, still open).
2. **Focus areas still point at tests.** In 4 of 10 PRs the Review Briefing's focus areas are
   only test methods, or alphabetical "Add A…" entries: mockito-3835, jackson,
   spring-boot-51490, and commons-lang with the test first (R5, still open).
3. **Behavioral labels can mislead.** All 9 gson methods are flagged BEHAVIORAL "branch
   removed" for an if-chain → `switch` refactoring. `ControlFlow` doesn't count `switch`
   cases, so a behavior-preserving rewrite reads as a behavior change (N2).
4. **"Modify body" is visible but mute.** keycloak's security-relevant policy trigger points
   now appear, but as three undifferentiated UNKNOWN "Modify body of …#process" entries among
   112 (N4).
5. **Architecture views are unchanged.** Modules are still first-path-segment names
   (`src`, `module`), the tech stack is "Unknown" for Gradle and single-module repositories,
   and there are **0 dependency rails in all 10 PRs** (R3, R11).

**What Athena is now uniquely good at.**
- **Relocation understanding**, still its standout: the petclinic move, keycloak's pull-up
  into new abstract bases.
- **Contract-level changes** a diff buries: jackson's six protected field *type* changes
  now read `MethodHolder -> MethodHandle (protected)`; mockito's nullness contract appears as
  one `+@Nullable` line per entry point.
- **Completeness guarantees:** a reviewer can now tell what Athena didn't cover.

**Where it still fails.**
- **Intent and ranking:** why the change was made, and which of 100+ entries matter.

## New findings

- **N1: Volume without ranking.** Full coverage roughly doubled the entries on large PRs.
  Test code accounts for a large share:
  - mockito-3835: 13 of 22 Changes are test methods and nested test fixtures.
  - petclinic: 7 of 9 body modifications are in tests.

  With R5 and R7 still open, more information isn't yet more understanding.
- **N2: `switch` isn't control flow.** `ControlFlow` counts `if`/`else` branches and loops but
  not `switch` cases, so gson's if→switch refactoring is reported as nine behavioral "branch
  removed" changes. The same blind spot means an edit to `switch` cases is only flagged
  incidentally: keycloak's `GrantTypeCondition#applyPolicy` gained new `case` labels, and was
  caught only because each new case contains an `if`.
- **N3: Order-dependent one-to-one matching.** keycloak's pull-up is attributed to different
  classes than in the baseline, with no code change in between. Only which files get parsed
  changed (#271). The move is real either way, but the description isn't stable across
  versions.
- **N4: "Modify body" says nothing about the body.** Every `MODIFY_METHOD_BODY` reads the same.
  A one-line summary of what changed inside (calls added/removed, a new `throw`, a new policy
  trigger) would turn keycloak's three trigger points from noise into its most important
  entries.
- **N5: Label mismatches.**
  - Parameter/method annotation changes map to the Structural concept "Change Signature", though the signature didn't change.
  - Adding `@Override` produces a `CHANGE_METHOD_ANNOTATIONS` entry (keycloak), which is noise.

## Prioritized next improvements

Ranked by how many corpus PRs each would change, now that coverage is no longer the
bottleneck:

| # | Improvement | PRs affected | Why now |
|---|---|---|---|
| 1 | **Rank and separate test code:** exclude or down-rank tests in focus areas, never infer capabilities from `src/test`, and group test changes under one collapsible entry per class (R5, R7, N1). | 9 | The biggest remaining gap between "everything is shown" and "the reviewer knows where to look". |
| 2 | **Summarize body modifications** by what changed inside: calls added/removed, new throws/returns (N4). | 6 | Turns the new UNKNOWN entries from noise into signal: keycloak's trigger points, spring-boot's wiring. |
| 3 | **Model `switch` in `ControlFlow`** (N2). | 2 | Removes gson's false behavioral flags; catches case-level edits. |
| 4 | **Aggregate repeated patterns and many-to-one pull-ups; make matching deterministic** (N3). | 4 | keycloak, spring-boot-51490, jackson: the same operation ×N should read once. |

| 6 | **Spring plugin:** Aware-interface injection, `@ConfigurationProperties` keys, `@Import` participants. | 2 | Unchanged from the baseline. |
| 7 | **Label hygiene:** its own concept for annotation-contract changes; ignore `@Override`-only changes (N5). | 3 | Cheap. |

## Limitations

These are the same as the baseline's: 10 PRs, a single agent evaluator, reading-effort
proxies instead of minutes, and AI features excluded. In addition:

- **Same evaluator for both runs.** The evaluator who implemented #260–#271 also scored this
  re-run. The Athena-side scores could be biased upward. The mechanical metrics above don't
  depend on judgement and should carry more weight.
- **Output-level only.** This re-run did not include a visual pass of the UI.
